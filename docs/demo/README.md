# Synthetic demonstration artifacts

| File | What it is |
|---|---|
| `run_synthetic_demo.sh` | The reproducible script: fictional company, generated fixture files, example.com-style URLs, no network, no real persons. Runs the real CLI binary with a fresh `TRACEFIELD_HOME`. |
| `DEMO_SESSION.txt` | A recorded terminal session of that script (plain text, captured with `script`, ANSI escapes stripped). Last refreshed 2026-11-10 against the current build. |
| `INGEST_CAPTURE.txt` | Raw capture of the 0.2 offline-ingest flow shown in the README's demo image: `case-import` of a Sherlock `--csv` capture into a fresh synthetic case, `case-import status`, then one `source promote` with recorded provenance. Captured 2026-11-10 with a scratch `TRACEFIELD_HOME` and input under `/tmp/tracefield-capture/`. |
| `SAMPLE_REPORT.md` | Verbatim Markdown report generated by the real CLI (`report demo --format markdown`) from the same recorded walkthrough session that produced `assets/demo-walkthrough.gif`. Read this before judging the output format: caveats, assessment labels with rule versions, evidence digests, and limitations are printed exactly as any operator would see them. |
| `USABILITY_PROTOCOL.md` | Test protocol for three independent first-run users — what to attempt, what to record. **No results exist yet; nobody has run this protocol.** |

Provenance of `INGEST_CAPTURE.txt` (2026-11-10, real CLI from the project
venv, no network):

- the import used a **byte-identical copy of**
  `tests/fixtures/ingest/sherlock_v0.16.2_killerdasher_2026-11-07.csv`
  (sha256 `29309604564665664f9757623b9ee67f63f08bd5c61c25a01da708b791d62add`),
  named `capture.csv` in a scratch `/tmp` directory so displayed paths stay
  temporary;
- `assets/demo-terminal.png` in the repository root README is a faithful
  **render** of this exact text — styling only (terminal chrome, prompt
  colour), no content edits;
- these artifacts are synthetic: the capture `killerdasher` is the project
  maintainer's own handle, used as the operator-owned test fixture (see the
  fixture's rotation policy in `docs/ingest/SHERLOCK_CSV_SCHEMA.md`).

### Walkthrough recording provenance (`assets/demo-walkthrough.gif`)

Captured 2026-11-10 in a single pass, and **not** simulated:

- a real `xterm` window ran a paced shell script whose steps invoke the real
  `tracefield` binary against a fresh synthetic case under
  `/tmp/tracefield-capture/` (no network; the only edit between command
  executions is a `sleep` for readability);
- the window was recorded by frame-grabbing its X11 window (`import`) at
  ~2 frames/second and assembled with `ffmpeg` (palette-optimized GIF,
  880 px wide) — no content, output text, or prompts were altered after
  capture;
- the same session's `report demo --format markdown` output is committed
  verbatim as `SAMPLE_REPORT.md`;
- to re-record: bring up the walkthrough script (the steps above), open an
  `xterm` sized to the recorded geometry, and frame-grab the window id —
  the capture depends only on X11 tooling (`xterm`, `xwininfo`, `import`,
  `ffmpeg`), none of which TRACEFIELD itself uses.
